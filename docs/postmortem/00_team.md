# Project 01 Post Mortem - Group 6/ Project1

## Context
We had set out to build a dictionary app. All users would be able to see a random word on their dashboard and had the ability to search words
and see definitions. Signed in users would have the ability to favorite words and add them to a list that they could access either through their dashboard or through their user page.
What we shipped was a dictionary app that allowed any user to be able to search words and then for logged in users they were able to see their user information in the user page and edit their account information. The random word on the dashboard was there but it was not randomized.

## What went well
1. Communication and division of work was pretty good between our team members. It helped because everyone knew what they should be working on and that helped 
with the flow of the project. We were able to get the requirements done and ended up having a working application at the end. 

## What went wrong
1. Not having enough time to complete the favorites feature for the application and our API ended up being super slow. - Cause: We had aimed too high with the amount of features we had wanted for the application and realistically was not going to be possible with our time constraint. We also had some misscommunication that affected how much we progressed. The API was chosen based on the information it provided and since it had what information we wanted for the application we just decided to use it and figured out that it was a bit too slow later on when it was a bit too late to change the API. 
## Advice to our next teams
1. Make sure to efficiently communicate with one another and be responsive. Set up times that work with all of you to meet outside of class if you guys can't seem to communicate well over slack.
2. Do not hesitate to give constructive feedback on your team member's PR's or code. If you feel that another way would be more efficient, suggest it.
